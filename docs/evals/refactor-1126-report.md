# 一篇讲义为什么会被发布成插图？

2026-11-26 · GenBox 网页粘贴入口与 GenBox-Open 本地作品库

《星座课》是一篇含 HTML 星图示例的 Markdown 教程。备份版本的发布表单把示例识别为独立网页，链接能打开，读者却看不到课程和练习。重构后的表单将它识别成 Markdown，回读的作品标题为《星座课》，练习也在原位。两次发布均发生在一次性本机实例。[备份发布记录](artifacts/backup-browser.json) · [重构发布记录](artifacts/refactor-browser.json)

## 同一组样本的三个版本

在同一台 arm64 Mac、同一个 Node 24.15.0 运行时，用同一脚本直接调用每个版本的粘贴函数。教师讲义和聊天回复是按问题手写的合成样本。每例同时检查全文、格式、标题，空输入检查空结果。备份和实际起点的目标源码 SHA-256 相同。语料针对已知问题设计，尚无用于推算线上误判率的流量抽样。

| 完整匹配的样本 | 备份 62bc2e8 | 实际起点 36bcb1a | 重构 49b2430 |
| --- | ---: | ---: | ---: |
| 常规输入 | 10/10 | 10/10 | 10/10 |
| 结构与文本边界 | 2/15 | 2/15 | 15/15 |
| 全部固定样本 | 12/25 | 12/25 | 25/25 |

新实现逐行跟踪代码围栏，按原文偏移提取外包装，只从代码块外采集文档标题。裸文件、自带示例的教程与聊天助手交付的独立网页各有一组对照。没有标题的教程和普通交付说明有时在文本结构上完全相同；这类输入可用上传原文件的入口保持意图。浏览器表单的文本字段还会把 LF 转成 CRLF，因此发布回读取回的讲义在统一换行后相等。[样本与逐条预期](artifacts/paste-corpus.json) · [备份原始返回](artifacts/backup-paste.json) · [动工前原始返回](artifacts/start-paste.json) · [重构原始返回](artifacts/refactor-paste.json)

## 三个面试角度

- **产品经理**可以从“链接生成成功，但交付物错了”谈起。把成功条件写成读者收到指定作品，才能解释为什么要检查标题、正文和练习，也能解释为什么要给含糊的输入保留文件上传入口。
- **AI Agent 开发**可以现场用本地 Skill 发布一份讲义、同链更新，再打开固定版链接。CLI 返回当前链接与固定版链接，SQLite 事务保护追加操作。托管上传需要明确选择目标地址；本机客户端对两个真实版本的服务完成了同一份 Markdown 的字节回读。[客户端备份联调](artifacts/backup-open-client.json) · [客户端重构联调](artifacts/refactor-open-client.json)
- **后训练与评测**可以展示最小反例及配对对照。仅把围栏外的讲义标题和练习换成交付说明，合理的期望就会改变。逐字段评分能指出格式、标题和正文哪项失配。对未知输入的泛化仍需独立标注的盲测集，本次没有训练模型。
